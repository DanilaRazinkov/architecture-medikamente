# Классификация данных и обоснование защиты

## Категоризация данных по степени критичности и требованиям защиты

| Категория данных                                              | Уровень конфиденциальности     | Тип данных            | Состояние данных                                                                    | Риск утечки | Инструменты защиты                                                                     |
|---------------------------------------------------------------|--------------------------------|-----------------------|-------------------------------------------------------------------------------------|-------------|----------------------------------------------------------------------------------------|
| **Медицинские сведения** (диагнозы, история болезни, анализы) | Специальная категория ПДн (L4) | Данные о здоровье     | At rest: файлы PDF/JPG, записи БД; In transit: передача между системами, интеграции | Критический | Шифрование AES-256 (хранилище), TLS 1.3 (передача), строгий RBAC/ABAC, детальный аудит |
| **Идентификационные данные** (ФИО, дата рождения, паспорт)    | Персональные данные (L3)       | ПДн                   | At rest: БД, Excel; In transit: API, веб-формы                                      | Высокий     | Шифрование полей в БД, токенизация, маскирование в интерфейсах                         |
| **Контактные данные** (телефон, email, адрес)                 | Конфиденциальные (L2)          | ПДн                   | At rest: БД, файлы; In transit: email, API                                          | Средний     | Шифрование, DLP для исходящих каналов, ограничение доступа                             |
| **Финансовые данные** (платежи, реквизиты)                    | Конфиденциальные (L3)          | Финансовая информация | At rest: 1С, БД; In transit: ККМ-интеграция                                         | Высокий     | TLS-шифрование, маскирование реквизитов, изоляция платежного шлюза                     |
| **Операционные данные** (записи, расписание, ТМЦ)             | Внутренние (L1)                | Бизнес-данные         | At rest: Excel, БД; In transit: внутренние сервисы                                  | Низкий      | Базовое шифрование, контроль доступа по ролям                                          |

## Обоснование необходимости защиты

**Медицинские данные** требуют максимальной защиты согласно ФЗ-323 (врачебная тайна) и ФЗ-152. Утечка может привести к
репутационным потерям, штрафам, уголовной ответственности по ст. 137 УК РФ.

**Идентификационные ПДн** подпадают под ФЗ-152: необходимо обеспечить конфиденциальность, целостность, доступность.
Риски: мошенничество, идентификационное воровство.

**Финансовые данные** связаны с прямой финансовой ответственностью. Интеграция с ККМ требует защиты каналов передачи
данных.

**Общий риск** для компании при утечке: потеря доверия клиентов, штрафы регуляторов, блокировка деятельности.

# Стратегия и инструменты защиты данных

## 1. Защита данных при хранении (At Rest)

| Объект защиты              | Данные                                 | Решение                                                                 | Инструменты                                                   |
|----------------------------|----------------------------------------|-------------------------------------------------------------------------|---------------------------------------------------------------|
| Файловые серверы           | Сканы, Excel, медицинские карты        | Шифрование на уровне диска и файловой системы                           | BitLocker (Windows Server 2022), EFS для папок пациентов      |
| Базы данных (PostgreSQL)   | Пациенты, записи, медицинские сведения | TDE (Transparent Data Encryption), шифрование на уровне таблиц/столбцов | pgcrypto, ключевой менеджмент через HashiCorp Vault           |
| Резервные копии            | Все данные                             | Шифрование бэкапов перед выгрузкой                                      | Veeam Backup & Replication с AES-256, хранение ключей в Vault |
| 1С (Бухгалтерия, Торговля) | Финансы, ТМЦ                           | Миграция в клиент-серверный режим, шифрование СУБД                      | SQL Server TDE или PostgreSQL TDE                             |

## 2. Защита данных при передаче (In Transit)

| Канал передачи               | Данные                       | Решение                                     | Инструменты                                             |
|------------------------------|------------------------------|---------------------------------------------|---------------------------------------------------------|
| Веб-приложения (портал, CRM) | Формы, API-запросы           | TLS 1.3 для всех соединений                 | Let's Encrypt/внутренний CA, настройка на Nginx/HAProxy |
| Интеграция с лабораторией    | Результаты анализов          | mTLS (взаимная аутентификация), API Gateway | Kong/APISIX, сертификаты из Vault PKI                   |
| Внутренние микросервисы      | Данные между сервисами       | Service Mesh с шифрованием                  | Istio/Consul Connect, автоматическое TLS                |
| Удаленный доступ сотрудников | Доступ к внутренним ресурсам | VPN с MFA                                   | WireGuard/OpenVPN, интеграция с Active Directory        |
| Электронная почта            | Конфиденциальные переписки   | Шифрование писем                            | S/MIME для Exchange, политики DLP                       |

## 3. Управление ключами шифрования

**Решение:** HashiCorp Vault в HA-режиме.

- Централизованное хранение ключей шифрования БД, сертификатов.
- Автоматическая ротация ключей (раз в 90 дней).
- Интеграция с Active Directory для аутентификации.
- Аудит всех операций с ключами.

# Средства автоматизированного контроля

## 1. DLP (Предотвращение утечек)

**Решение:** Поэтапное внедрение:

1. **Фаза 1:** Сигнатурный анализ (блокировка отправки файлов с мед.данными на внешние почты).
2. **Фаза 2:** Контентный анализ на основе ML (распознавание медицинских терминов, ПДн).
3. **Фаза 3:** Контекстный анализ (аномалии в поведении пользователей).

**Инструменты:**

- **Для сети:** Suricata с кастомными правилами.
- **Для почты:** Модули для Exchange Server.
- **Для endpoint:** Агенты на рабочих станциях (опционально, при расширении штата).

## 2. Мониторинг и аудит доступа

| Что мониторим          | Решение                                                     | Инструменты                              |
|------------------------|-------------------------------------------------------------|------------------------------------------|
| Доступ к БД            | Логирование всех запросов к чувствительным таблицам         | pgAudit + отправка логов в ELK           |
| Доступ к файлам        | Аудит операций с файлами в ключевых папках                  | Windows Server Auditing, ELK для анализа |
| API-запросы            | Логирование всех вызовов API, особенно к медицинским данным | API Gateway (Kong) + Elastic Stack       |
| Действия пользователей | Сбор логов аутентификации, изменения данных                 | Windows Event Log, Syslog, ELK           |

## 3. Обнаружение аномалий

**Реализация на базе Elastic Stack:**

- Machine Learning jobs для выявления аномальных паттернов (например, массовое скачивание медкарт).
- Оповещения в Telegram/Email через Alertmanager.
- Интеграция с тикет-системой для автоматического создания инцидентов.

## 4. Автоматизированные проверки соответствия

**Проверки по расписанию (через Ansible/Airflow):**

- Наличие шифрования на всех дисках с данными L3+.
- Актуальность TLS-сертификатов.
- Настроен ли аудит для критичных таблиц БД.
- Ротация ключей в Vault.

## План внедрения (дорожная карта)

**Фаза 1 (1-2 месяца):** Критичная защита

1. Настройка BitLocker на файловых серверах.
2. Включение TDE в PostgreSQL, настройка pgAudit.
3. Развертывание ELK для централизованного сбора логов.
4. Переход на TLS 1.3 для всех веб-сервисов.

**Фаза 2 (3-4 месяца):** Расширенная защита

5. Внедрение HashiCorp Vault для управления ключами.
6. Настройка VPN (WireGuard) для удаленного доступа.
7. Внедрение API Gateway (Kong) для защиты интеграций.
8. Настройка базовых правил DLP (сигнатурный анализ).

**Фаза 3 (5-6 месяцев):** Углубленный контроль

9. Настройка мтLS для внутренних сервисов и интеграций.
10. Внедрение ML-моделей для обнаружения аномалий в ELK.
11. Автоматизация проверок соответствия требованиям ФЗ-152.
12. Проведение пентеста и корректировка мер.
